# fullstack-coding-standards

## Reglas
- Cambios mínimos, tipado explícito cuando corresponda, nombres claros y separación de responsabilidades.
- Buscar componentes, hooks, repositorios y utilidades existentes antes de crear otros.
- No inventar endpoints ni contratos de respuesta.
- Reutilizar estilos y componentes existentes del sistema de diseño; evitar duplicar lógica.
- Para SQL/HTTP consultar `capstone-http-sql-reuse`; para pruebas `testing-audit-guardian`.

## Referencias
- `references/legacy-original.md` conserva reglas anteriores para revisión, no todas vigentes.
